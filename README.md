# 自己改良型機械システム開発計画レポート

**— Graph IR による機械の自己実装・自己改良の実験的研究 —**

---

## 0. 本研究の目的と位置づけ

### 0.1 研究目的

本研究の目的は、

> **機械が、機械自身の実装（構造・パラメータ・学習過程）を  
> 機械自身によって再生産・改良する最小実験系を構築すること**

にある。

特に、人間可読性・人間介在を前提としない  
**機械フレンドリーな中間表現（Graph IR）**を中核に据え、

- 構造の生成・変異
- 評価
- 選択
- 再生成

の閉ループを実装する。

---

### 0.2 研究背景

- LLM によるコード生成は進展しているが、**自己改良はタスクレベルに留まっている**
- NAS / AutoML は存在するが、**IR 自体が自己改良対象になる設計は未成熟**
- 再帰的自己改善（RSI）は理論的議論が先行し、**実装レベルの最小核が欠けている**

本研究は、これらの空白領域を **実装主導で埋める試み**である。

---

## 1. 基本設計思想

### 1.1 人間理解可能性を要件としない

- Graph IR は人間が読む必要はない
- 正しさは **型・制約・評価関数**によって担保される
- 記号的意味より **操作可能性**を優先する

---

### 1.2 「コンパイル以前」の表現を採用

- AST / ソースコードよりも下位の表現
- 勾配以前・意味以前のレベル
- **変異が直接作用できる構造**

→ Graph IR + Tensor Attribute

---

### 1.3 自己改良の最小核

以下が成立すれば「自己改良が起きている」とみなす：

1. 構造が自律的に変化する
2. 変化が評価によって選別される
3. その結果、次世代の変化が変わる

---

## 2. Graph IR 設計（要約）

### 2.1 表現形式

- 有向グラフ（原則 DAG）
- ノード：演算・制御・恒等・noop
- エッジ：データ依存・制御依存

---

### 2.2 ノード構成

| 要素        | 内容               |
| ----------- | ------------------ |
| op_type     | 演算種別（離散）   |
| attrs       | ハイパーパラメータ |
| tensor      | 学習可能パラメータ |
| constraints | shape / type       |

---

### 2.3 特徴

- **自己書換可能**
- **差分が明確**
- **部分評価が可能**

---

## 3. Mutation 設計計画

### 3.1 基本原則

- 局所性
- 型保存
- 意味保存または意味拡張
- 可逆性

---

### 3.2 採用する mutation カテゴリ（段階的）

#### Phase 1（安全）

- Attribute noise
- Activation swap
- Identity insertion

#### Phase 2（拡張）

- Subgraph rewrite
- Skip edge insertion

#### Phase 3（高度）

- Macro mutation
- 新ノード型生成

---

### 3.3 Mutation の学習

- mutation を「行為」としてログ化
- `(graph_before, mutation_type) → Δfitness` を記録
- mutation policy を更新

→ **進化の進化**

---

## 4. Fitness 設計計画

### 4.1 基本構成（多目的）

Fitness は以下の要素の線形結合として定義する：

- Performance
- Stability
- Evolvability
- Complexity（ペナルティ）

---

### 4.2 各要素の役割

| 要素         | 目的                   |
| ------------ | ---------------------- |
| Performance  | 短期的な有用性         |
| Stability    | 変異に対する壊れにくさ |
| Evolvability | 将来の改良可能性       |
| Complexity   | 過剰な構造肥大の抑制   |

---

### 4.3 安全装置

- NaN / 発散が検出された個体は即時除外
- 出力が定数化・崩壊した個体を除外
- 世代内多様性が低下した場合のペナルティ導入

---

## 5. 探索アルゴリズム計画

### 5.1 採用方式

**(μ + λ) 型 GA + 局所 ES + 多様性制御**

---

### 5.2 必須要素

- エリート保持
- Speciation（構造クラスタリング）
- Fitness sharing
- Novelty injection
- Mutation rate の自己適応

---

## 6. PoC 実装計画

### 6.1 目的

- 正しさではなく **回ること** を重視
- スケールではなく **挙動の観測** を重視

---

### 6.2 技術スタック

| 領域 | 技術                        |
| ---- | --------------------------- |
| 言語 | Python                      |
| IR   | Protobuf + Python           |
| NN   | PyTorch + PyTorch Geometric |
| 探索 | Custom GA                   |
| ログ | JSON / TensorBoard          |

---

### 6.3 実装フェーズ

#### Phase A：最小 PoC

- Dummy task
- 超軽量評価
- mutation 2〜3 種

#### Phase B：安定化

- 多様性指標の導入
- Fitness 分解
- 局所 ES の導入

#### Phase C：拡張

- mutation policy の学習
- fitness 重みの進化
- Graph IR 自己拡張

---

## 7. 想定される困難と対策

### 7.1 早期収束

→ Novelty / Speciation による回避

### 7.2 評価ノイズ

→ 軽量 proxy 評価 + seed 固定

### 7.3 構造崩壊

→ 型制約 + Stability 項による抑制

### 7.4 計算資源不足

→ 部分評価 / 差分評価

---

## 8. 成功判定基準（研究的）

以下が観測されれば成功とみなす：

- 構造多様性の自然発生
- 中立変異の蓄積
- Fitness の非単調だが上向きな推移
- Mutation 成功率の自己調整

---

## 9. 将来的拡張（研究フェーズ）

- Graph IR の自己拡張
- Self-hosting compiler
- メタ学習による探索制御
- 複数目標・複数環境での進化
- 他システム（LLM / Compiler）との接続

---

## 10. 総括

本計画は、

> **「シンギュラリティ」を抽象論ではなく  
> 実装可能な最小システムとして捉え直す試み**

である。

完全な自己改良に至らずとも、

- 自律的構造変化
- 評価に基づく選択
- 改良の改良

が成立した時点で、  
**質的に新しい計算機システム**が観測される。
